## Concrete public-source inputs

Reconcile commands with [TI feature evidence](../reference/library-ti-features.md)
and [EVIDENCE](EVIDENCE.md). Independent LED0 mode 8 needs field bit 6 and must
not disappear through erroneous mask `0x0038`; named reserved LED3 drive fields
must not appear as legal controls. Odd-nibble enable must not replay the SDK's
inverted setter. WoL mask `0x0800` alone does not define acknowledgement value;
use exact-part W0C/W1S rules and byte order. CLI tests must challenge these
source defects rather than merely round-trip shared metadata.

## Closed work unit

Add discoverable grouped typed routes for read-only selftest, loopback, BIST,
manual/automatic cable diagnostics and the complete programmable IRQ, LED/GPIO,
clock/interface, power, wake and EEE/LPI controls. Include repeater,
quality/link-loss and electrical compliance/calibration routes where the
exact-part ledger requires them, with explicit stimulus admission. Reconcile
against the full register/field/procedure denominator, including feature recipes
and legal settings unused by the first board. A raw write command is not a
feature implementation, and runtime opt-in does not mean optional scope.

Every handler validates tokens, cross-field legality and exact-part capability
before transfers. Report absent silicon support, missing software and absent
board/backend/fixture as different facts. Unconnected IRQ/clock pins do not
remove generic command paths. Reuse typed public operations and the single
owner; do not create CLI-only setters, direct uncoordinated MDIO or another
diagnostic state machine.

Disruptive stimulus, power/clock changes, raw writes and resets require explicit
maintenance admission and reject an active application session, busy operation
or retained result before I/O. Clearly distinguish read-only checks from
link-disrupting tests. Report diagnostic validity, operation completion,
uncertain effects and primary versus restoration failure independently; cleanup
success cannot turn a failed command into success. Preserve consumed event
samples and exact mixed command/status semantics through existing procedures.

Update ledger rows with exact variant/mode, legal values, public method/field,
CLI/help, owner route, record, independent host case and physical requirement.
Required omissions stay open until filled; neither the initial P4 configuration
nor the vendor reference driver defines the maximum feature set.
